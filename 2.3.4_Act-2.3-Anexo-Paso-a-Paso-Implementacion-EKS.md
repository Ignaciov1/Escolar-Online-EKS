## Paso 1: Verificar/Crear VPC y Subredes

Si ya tienes la VPC de EA1, puedes reutilizarla. Si no, crear una nueva:

- VPC: `escolaronline-vpc` (10.0.0.0/22)
- 2 subredes publicas (AZ1a, AZ1b) — para ALB Ingress
- 2 subredes privadas APP (AZ1a, AZ1b) — para nodos EKS
- 2 subredes privadas DATA (AZ1a, AZ1b) — para RDS
- Internet Gateway + NAT Gateway

**Importante:** Las subredes deben tener tags para que EKS las reconozca:

```bash
# Subredes publicas (para ALB)
aws ec2 create-tags --resources <SUBNET_PUB_1A> <SUBNET_PUB_1B> \
  --tags Key=kubernetes.io/role/elb,Value=1

# Subredes privadas APP (para nodos)
aws ec2 create-tags --resources <SUBNET_PRIV_APP_1A> <SUBNET_PRIV_APP_1B> \
  --tags Key=kubernetes.io/role/internal-elb,Value=1
```

## Paso 3: Crear RDS MySQL Multi-AZ

1. Ir a **RDS** → **Create database**
2. Configurar:

| Campo | Valor |
|-------|-------|
| Method | Standard create |
| Engine | MySQL |
| Version | MySQL 8.0.x |
| Template | Dev/Test |
| DB instance identifier | escolaronline-db |
| Master username | alumno |
| Master password | alumno123 |
| Instance type | db.t4g.micro |
| Storage | 20 GB gp3 |
| Multi-AZ | Yes |
| VPC | escolaronline-vpc |
| Subnet group | Crear nuevo con subredes privadas DATA |
| Public access | No |
| Security group | SG-RDS |
| Database name | escolar_online |
| Encryption | Enabled (aws/rds) |

3. Esperar que el estado sea **Available** (~10 min)
4. **Anotar el Endpoint** (ej: `escolaronline-db.xxxxxx.us-east-1.rds.amazonaws.com`)

## Paso 5: Crear Cluster EKS

### Opcion A: eksctl (recomendada)

```bash
eksctl create cluster \
  --name escolaronline-cluster \
  --region us-east-1 \
  --version 1.29 \
  --nodegroup-name escolaronline-nodes \
  --node-type t4g.small \
  --nodes 2 \
  --nodes-min 2 \
  --nodes-max 4 \
  --managed \
  --vpc-private-subnets <SUBNET_PRIV_APP_1A>,<SUBNET_PRIV_APP_1B> \
  --vpc-public-subnets <SUBNET_PUB_1A>,<SUBNET_PUB_1B>
```

> Nota: Este comando toma ~15-20 minutos. Crea el cluster + node group + configura IAM roles.

### Opcion B: Consola AWS

1. EKS → Create cluster → nombre, version, VPC, subredes, security group
2. Luego: Add Node Group → tipo instancia, min/max nodos

### Configurar kubectl

```bash
aws eks update-kubeconfig --name escolaronline-cluster --region us-east-1
kubectl get nodes
```

Resultado esperado: 2 nodos en estado `Ready`.

## Paso 6: Crear Repositorios ECR y Push Imagenes

```bash
# Desde tu PC local (carpeta desarrolloApp-ACT2.3/)

chmod +x ecr-push.sh
```

O manualmente:

```bash
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
REGION="us-east-1"

# Login ECR
aws ecr get-login-password --region $REGION | docker login --username AWS --password-stdin $ACCOUNT_ID.dkr.ecr.$REGION.amazonaws.com

# Crear repos
aws ecr create-repository --repository-name escolaronline-frontend --region $REGION
aws ecr create-repository --repository-name escolaronline-get-products --region $REGION
aws ecr create-repository --repository-name escolaronline-create-product --region $REGION
aws ecr create-repository --repository-name escolaronline-update-product --region $REGION
aws ecr create-repository --repository-name escolaronline-delete-product --region $REGION

# Build ARM64 (desde carpeta 01-ea1/desarrolloapp/)
docker build --platform linux/arm64 -t escolaronline-frontend ../01-ea1/desarrolloapp/frontend
docker build --platform linux/arm64 -t escolaronline-get-products ../01-ea1/desarrolloapp/get-products
docker build --platform linux/arm64 -t escolaronline-create-product ../01-ea1/desarrolloapp/create-product
docker build --platform linux/arm64 -t escolaronline-update-product ../01-ea1/desarrolloapp/update-product
docker build --platform linux/arm64 -t escolaronline-delete-product ../01-ea1/desarrolloapp/delete-product

# Tag + Push (repetir para cada imagen)
docker tag escolaronline-frontend $ACCOUNT_ID.dkr.ecr.$REGION.amazonaws.com/escolaronline-frontend:latest
docker push $ACCOUNT_ID.dkr.ecr.$REGION.amazonaws.com/escolaronline-frontend:latest
# (repetir para las otras 4)
```

## Paso 7: Actualizar Manifiestos con valores reales

Antes de aplicar los manifiestos, reemplazar los placeholders:

### En configmap.yaml:
- `<RDS_ENDPOINT>` → endpoint real de RDS (ej: `escolaronline-db.xxxxxx.us-east-1.rds.amazonaws.com`)

### En todos los *-deployment.yaml:
- `<ACCOUNT_ID>` → tu Account ID de AWS (ej: `123456789012`)

Puedes hacerlo con sed:

```bash
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
RDS_ENDPOINT="escolaronline-db.xxxxxx.us-east-1.rds.amazonaws.com"

cd 02-ea2/desarrolloapp/k8s/

# Reemplazar ACCOUNT_ID en deployments
sed -i "s/<ACCOUNT_ID>/$ACCOUNT_ID/g" *-deployment.yaml

# Reemplazar RDS_ENDPOINT en configmap
sed -i "s/<RDS_ENDPOINT>/$RDS_ENDPOINT/g" configmap.yaml
```

## Paso 9: Instalar AWS Load Balancer Controller

El ALB Ingress Controller crea automaticamente un ALB cuando aplicas un recurso Ingress.

```bash
# Instalar cert-manager (prerequisito)
kubectl apply --validate=false -f https://github.com/jetstack/cert-manager/releases/download/v1.12.0/cert-manager.yaml

# Instalar AWS Load Balancer Controller
# (seguir guia oficial: https://kubernetes-sigs.github.io/aws-load-balancer-controller/)

# Verificar que esta corriendo
kubectl get pods -n kube-system | grep aws-load-balancer
```

> Nota: En AWS Academy, el ALB Controller puede requerir configuracion adicional del IAM role (LabRole ó labInstanceProfile). Consultar documentacion del lab.

Si al ejecutar los comandos de este paso se obtienen errores de permisos (AccessDenied o IAM), **omitir este paso y continuar con la validacion final**. ## Troubleshooting

| Problema | Causa probable | Solucion |
|----------|---------------|----------|
| Pods en CrashLoopBackOff | No conecta a RDS | Verificar configmap (RDS_ENDPOINT), SG-RDS permite 3306 desde SG-EKS |
| Pods en ImagePullBackOff | No puede descargar imagen ECR | Verificar IAM role del node group tiene permisos ECR |
| Ingress sin ADDRESS | ALB Controller no instalado | Instalar AWS Load Balancer Controller |
| HPA muestra unknown | Metrics server no instalado | `kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml` |
| Nodos NotReady | Subredes sin NAT Gateway | Verificar route table privada apunta a NAT GW |
| Timeout al acceder ALB | Subredes publicas sin tag | Agregar tag `kubernetes.io/role/elb=1` a subredes publicas |
